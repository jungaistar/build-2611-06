6. 한계와 남은 일

  • 서버 DB 가 아닙니다 — 이 브라우저와 파일에만 있습니다. 여러 사람이 동시에 고치는 공용 저장소는 사내 서버 몫이며, 이 도구는 양식 → 항목 → 팀별 배포 → 병합까지입니다.
  • 수식은 사칙연산 · 셀 참조 · IF 까지만 따라갑니다. 다른 시트 참조 · SUM 등은 「수식 미지원」.
  • 단위 환산과 값의 공학적 타당성은 보지 않습니다(숫자인지만).
  • 양식은 엑셀에서 고쳐 다시 올립니다. 이미 만든 프로젝트의 항목은 바뀌지 않습니다.
  • 기획자 양식 원본은 저장소에 없습니다 — 화면에서 올려 쓰고, 저장소의 예제 양식은 가상입니다.
  • 업무 자료는 지금처럼 브라우저 안에서만 처리합니다. 로그인 DB 에는 「누가 쓸 수 있는가」와 게시판 글만 있습니다.
  • 로그인 뒤 화면(게시판 · 관리 · 첫 화면 고르기)은 실제 계정으로 눌러 보지 않았습니다. 가입 → 사용 신청 → 승인 → 게시판 글쓰기 확인은 기획자와 관리자 몫입니다.
  • 독립 운영까지 남은 것: 본인 Supabase 프로젝트에 auth.sql · board.sql · site.sql 실행 → js/auth-config.js 의 url · anonKey 교체 → 다시 배포(supabase/README.md)
